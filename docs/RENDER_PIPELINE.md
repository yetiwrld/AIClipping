# Render Pipeline

Rendering is FFmpeg-driven, fully local, and happens in a spawned subprocess —
the UI never blocks and never runs FFmpeg synchronously.

## Binary resolution

`Settings → Advanced` override → system `PATH` → bundled
`@ffmpeg-installer` binary. FFprobe resolves the same way. The active binary
and its version are shown in Settings and in the diagnostic export. If nothing
is found, rendering is disabled with an actionable error (not a crash).

## Filter graph

```
input (source/source.<ext>)
  → seek/trim            -ss <start> -to <end>  (input seeking for speed,
                         re-encode makes it frame-accurate)
  → reframe              scale + crop to 1080×1920 (9:16):
                         vertical slice of width = ih * 9/16, x offset driven by
                         crop_mode (center/top/bottom/manual focus + zoom),
                         then scale to 1080×1920 with lanczos
  → captions             subtitles filter burning an ASS file generated from the
                         clip's caption configuration (style, position, size,
                         emphasis, per-cue text edits)
  → audio                aac 192k, optional loudnorm (EBU R128), stream copy
                         never used (we re-encode for frame-accurate trim)
  → encode               libx264, crf 18, preset veryfast (configurable),
                         yuv420p, +faststart, 1080×1920
  → out                  projects/<id>/renders/<render-id>.tmp.mp4
```

GPU acceleration: encoder probe (`ffmpeg -hide_banner -encoders`) looks for
`h264_nvenc / h264_qsv / h264_videotoolbox / h264_amf`; if the user enables
hardware encoding and a render fails, the error offers an automatic CPU
fallback retry. CPU is the default and always available.

## Safety properties

- **Atomic completion**: output is written to `<id>.tmp.mp4`; only a zero-exit
  FFmpeg run is renamed to `<id>.mp4` and recorded as `completed`. A failed or
  cancelled render leaves no corrupt "finished" file (temp is deleted).
- **Non-destructive**: sources are only ever read.
- **Cancellation**: `SIGTERM` → 5s grace → `SIGKILL`; temp cleaned; task marked
  `cancelled`; project state untouched.
- **Progress**: `-progress pipe:1 -nostats` on stdout; `out_time_us` /
  expected duration → 0–1 progress + current stage, streamed over the event
  bus (`render:progress`) and persisted (throttled).
- **Failure attribution**: stage tracked through
  `preparing → probing → filters → encoding → finalizing`; failure reports
  include what happened, likely causes, and a "technical details" disclosure
  of the FFmpeg stderr tail (last ~80 lines).
- **Retry** re-queues with the same settings snapshot.

## Render queue

- Concurrency configurable (default **1** — avoids saturating CPU/disk; a
  note explains the trade-off).
- States: `queued → preparing → rendering → completed | failed | cancelled`.
- Persisted in the `renders` + `tasks` tables; app restart marks in-flight
  renders `interrupted` and offers resume/restart in the recovery UI.

## Caption rendering

- ASS subtitles generated by `src/main/services/rendering/ass.ts` from the
  clip's caption config: style preset (Classic, Bold, Minimal, High Impact,
  Podcast, Clean) + overrides (font size, Y position, emphasis on/off,
  uppercase, max words per cue).
- Word-level emphasis: per-word inline color overrides timed from word
  timestamps (proportional distribution when the provider didn't supply them).
- Bundled OFL font (Inter, `resources/fonts`) is passed via `fontsdir` for
  deterministic output across machines; system fonts are a fallback.
- The editor preview renders the **same segmentation** in DOM (shared module)
  so preview ≈ output; minor anti-aliasing differences only.
- SRT sidecar export for platforms that want caption files.
